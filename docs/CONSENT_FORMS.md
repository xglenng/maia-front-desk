# Artist consent forms

`/waivers`, available from More, supports two consent workflows independent of SMS opt-in:

- **External form link:** each artist can add a public HTTPS link from Jotform, Google Forms, Typeform, Square, or another provider. This links to the existing form; it does not scrape or convert the provider’s questions. Completion is manual unless the studio owner configures the existing verified Jotform integration. Shared provider credentials and webhook rotation remain owner-only.
- **Maia form:** each artist creates an immutable form from reviewed consent text. Clients acknowledge the text, enter their full legal name, and draw a signature using a finger, stylus, or mouse. The Clear button resets the drawing. Changing wording requires creating a new form and deactivating the old routing rule so prior signed evidence stays intact. The searchable Add element panel supports up to 40 elements: headings, text blocks, dividers, full names, email, phone, address, date, number, short and long text, dropdowns, single-choice and multiple-choice questions (2–20 unique choices), and acknowledgments. The mandatory signature and full legal name remain fixed at the bottom. Contact fields are stored as form responses; they do not silently overwrite client records or grant SMS consent. Artists build directly on a live form canvas: selecting an element opens its settings, edits appear immediately, and elements can be reordered or made required. The canvas reuses the client field renderer. Form name and consent wording are edited directly on the canvas; there is no separate preview toggle. Server validation rejects missing required answers, invalid choices, wrong value types, and unknown question IDs. Signed evidence includes both the immutable definition and normalized responses. This version does not include conditional logic or medical questionnaires. A single Photo ID element supports an optional or required private JPEG/PNG upload with the signed form; see `CONSENT_STARTERS_AND_PHOTO_IDS.md` for encryption, access, storage, and release requirements. Guardian wording and legal suitability remain the studio’s responsibility.

Artists manage only their assigned artist forms. Owners retain studio-wide access. Forms route to appointments by artist, service, and audience. An appointment form link may be created without sending a message or obtaining SMS opt-in. Sending SMS still uses the existing consent checks and studio messaging configuration. Do not treat a signed procedure form as SMS permission.

Hosted links contain 192-bit random bearer tokens stored as SHA-256 digests. Keep links private. They expire seven days after the appointment and stop working if the assignment is voided, the form deactivated, or the appointment cancelled/no-show. Public responses exclude client identities. Signatures require same-origin submission, explicit agreement, a bounded full name, and a non-empty drawn signature; the server derives tenant, client, and appointment from the token. A transaction locks the assignment and stores one submission, the exact consent text, signature acknowledgement, bounded normalized drawing strokes, timestamp and document hash, then marks the assignment complete and cancels waiver reminder jobs. Repeat signing is idempotent. Hosted forms cannot be manually marked complete.

No database schema migration is required: this extends existing waiver templates, external form routing metadata, assignments, submissions, and events. No live provider requests or messages are required to deploy. Rollback restores the previous code; do not delete existing form or signature records. Previously issued Maia links require this version to remain usable.

Validation uses the normal typecheck/build/test scripts plus the optional isolated PostgreSQL integration test:

`MAIA_FORMS_TEST_SOCKET=/private/tmp/maia-forms-XXXXXXXX node --import tsx --test packages/waivers/__tests__/forms-postgres.test.ts`

The test requires a fresh database named `maia_forms_test` on port 55449 in that local socket directory. It asserts the local data directory, seeds only synthetic records, and forbids provider fetches. It covers artist/tenant denial, external URL validation, private link creation without SMS consent, valid and invalid signatures, concurrent retries, and transaction rollback.

Signature drawings are stored as validated numeric strokes, not user-provided SVG or image markup. The server rejects empty or stationary drawings, out-of-range coordinates, and excessive stroke/point counts. The stored strokes are included in the document hash. Existing signed records retain their original signature format. Unsigned links use the new drawing requirement.

## Signed form archive

Open `/waivers/archive` from the Signed forms section on `/waivers`. The archive lists stored Maia submissions across all appointment dates, newest first, with search by signer, artist, or form name and 25 records per page. Owners see their studio's submissions; artists see only submissions for appointments assigned to their user. Other roles are denied. List responses omit signature evidence; opening a record loads the saved form snapshot, answers, drawn signature, timestamp, template version, and document hash through an authenticated, tenant-scoped endpoint. Responses are private and not cached.

Use **Print / Save PDF** for a readable copy, or **Download record (JSON)** for the stored evidence. Photo IDs remain separate private downloads through the existing authorized endpoint. Older submissions without a native definition or drawn signature show an explicit unavailable notice rather than reconstructing evidence from the current template. External-provider signed documents remain with their provider. No schema migration or retention changes are needed for this archive.

Validation: the isolated PostgreSQL consent test covers owner/assigned-artist access, other artist/tenant denial, anonymous denial, search, pagination, invalid IDs, private response headers, and evidence download. The archive does not send client messages or automatically mark forms reviewed.
