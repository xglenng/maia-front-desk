# Maia Home Screen app

The public `/install` page explains installation. `/manifest.webmanifest` declares standalone display and an `/inbox` launch URL. Opaque, versioned PNGs in `/brand/v1/` provide the Apple touch icon, favicon, Android icons and separate padded maskable icons. Legacy `/app-icon/180`, `/app-icon/192`, and `/app-icon/512` URLs redirect to the corresponding new artwork. The 440px master is extracted from the approved rightmost concept, with the presentation border and board removed; `node --import tsx scripts/generate-brand-assets.ts` regenerates the sizes from it. Increment the asset directory version when artwork changes to avoid stale caches.

This is an online Home Screen web app, not an App Store binary. It has no service worker, offline cache, or push notifications. Customer messages and authenticated pages are not cached by a new offline layer.

After an approved deployment, use `https://app.maia.gavakatasoftware.com/install` for the **Install Maia** link. Installation must occur on Maia's origin; adding the marketing site itself to Home Screen will not install Maia. Passkeys are scoped to this app hostname and do not transfer to a Home Screen shortcut installed from another origin. Review existing links and shortcuts before enabling passkeys.

The server-rendered head includes `apple-touch-startup-image` links for iPhone 12 and newer (including SE 3), in portrait and landscape: 375×667 @2x and 360×780, 390×844, 393×852, 402×874, 420×912, 428×926, 430×932 and 440×956 @3x. These are native Home Screen launch images, separate from the React session-loading screen. Both use the same near-black background and centered emblem. The session check has a 15-second failure timeout and offers retry/sign-in; subsequent navigation does not remount the launch screen. It does not cache authenticated responses.

Apple's [archived Safari documentation](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html) describes startup-image metadata, but does not guarantee current iOS behavior or scaling. iOS may instead show a previous snapshot, and unlisted/new device dimensions have no custom image. Android selects the manifest icon and background; its maskable safe zone follows [web.dev's guidance](https://web.dev/articles/maskable-icon). Browsers do not display iOS startup images.

Verify on a physical iPhone: open the install URL in Safari, Share → Add to Home Screen, enable Open as Web App if offered, Add. Cold-launch in both orientations, sign in, verify inbox, drafts, calendar, sign out, and relaunch. Also test Android installation and Safari. Desktop browser and mocked-session checks cannot confirm physical-device startup behavior. iOS and Android may retain old icons or snapshots: users may need to remove and add the Home Screen app again. No database migration is needed. Roll back by redeploying the preceding release; existing Home Screen shortcuts may remain on users' devices.
